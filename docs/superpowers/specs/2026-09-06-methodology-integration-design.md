日期：2026-09-06
状态：设计已获用户批准（方向：增强生成能力；培训课件生成器不在本期范围）
来源素材：Obsidian `10.Projects/培训/数据分析方法论/`（数据分析培训大纲 v3.0、数据化运营-数据分析、数据化运营-落地执行；源文档不入库）

## 1. 目标

把用户自总结的数据分析方法论提炼为**可执行分析规则库**，嵌入 data2ppt 生成流水线的分析层：以后生成的每份 PPT 都按用户自己的方法论做数据分析与组织叙事。纯文档改动，零代码。

## 2. 新增产物：`methodology/analysis-methodology.md`

规则库按分析时序组织为七节，每条规则标注来源模块与接入点：

### §A 数据可信前置检查（来源：大纲模块一；接入：Phase A 第一步，异动归因类必跑）
- 异动真实性核查：数据采集/ETL/上报链路确认；多数据源交叉验证；结论写入 `facts.json` 的 `quality_check` 字段（`{stability, outliers, link_check}`）
- 稳定性阈值：CV<15% 高稳定 / 15–30% 中等 / ≥30% 低稳定需谨慎；结论影响标题措辞（低稳定指标的变化不得写成确定性结论）
- 异常值检测：3σ（正态）/ IQR（非正态）；被剔除的异常值必须在口径注中披露
- 不稳定 → 大纲阶段标注"暂定"，并说明需要更长周期数据

### §B 三比分析法（来源：数据化运营-数据分析 模块二；接入：自动探查的对比维度框架）
- 自己比：同比/环比/定基比（时间序列）
- 标杆比：业务目标、盈亏平衡点、历史最优
- 市场比：竞品、行业均值
- 事实清单中每个对比结论标注属于哪一比；只有单一对比的 deck 须说明为什么其他两比不可得

### §C 七步成诗法（来源：数据化运营两文档；接入：分析骨架）
- 界定问题 → 分解问题 → 优先排序 → 关键分析 → 归纳建议 → 工作计划 → 效果检视
- 与金字塔的关系：**分析按七步走，呈现按金字塔**；§IX 大纲中每页可标注对应的七步阶段
- "优先排序"步骤产出优先级表（§F 矩阵），"工作计划/效果检视"映射到行动页的落地规则与后续验证

### §D 三不原则（来源：模块二；接入：质量红线）
- 不用事实解释事实：页面只放结论与关键证据，不放过程的复述
- 不用偶然代表必然：单点波动不下趋势结论；未验证的根因必须标注假设/暂定
- 不用角度限制观点：行动建议须可执行，不得以"角度不同"拒绝给建议

### §E 归因报告模板映射（来源：大纲 4.5；接入：归因类 deck 页面角色扩展）
- 完整六段：异动概述 → **数据质量核查**（新增角色）→ 下钻分析 → **假设验证**（新增角色，列假设清单与验证结论）→ 归因结论 → 建议行动
- 面向决策者：仍压缩为 冲突→放大→归因→行动 四段；六段完整版仅在用户要求"给分析师看"时使用
- 风格工作区 §III 页面角色词表新增：数据核查、假设验证

### §F 优先排序矩阵（来源：客户到店率案例；接入：行动页排序）
- 排序 = 提升空间 × 操作难度；提升空间大+难度低 = 第一优先
- 大纲确认时向用户展示排序依据；行动页可附一行排序理由

### §G 行动三分类与落地方式（来源：模块三；接入：行动页分组标签）
- 动作方向：拓展类 / 优化类 / 剔除类
- 落地方式：分类·排序 / 模式·策略 / 机制·预警
- 行动页每个建议可带其中一个分类标签；≥3 条建议时按三方向分组

### §H 分析逻辑顺序与 6 秒测试
- 自动探查执行顺序：先看结构 → 再看漏斗 → 再看画像
- 6 秒测试：交付前渲染目检新增检查项——每页 6 秒内能否答出"这页说了什么"

## 5. 验收

用 `examples/gmv_weekly.csv`（虚构样例）重跑一次端到端，检查：
1. facts.json 出现 `quality_check` 字段
2. 大纲体现三比框架（自己比/标杆比至少各一处或说明不可得原因）
3. 行动页建议带拓展/优化/剔除分类标签且按优先矩阵排序
4. 渲染目检含 6 秒测试
